Install Android to a Virtual Disk

The virtual machine window is now open. Follow these 6 steps once; ApkBolt will then boot directly from the disk without needing the ISO again.

  1. Boot menu: Use ↓ to select Installation - Install Android-x86 to harddisk and press Enter
  2. Choose Partition: Select Create/Modify partitions; when asked about GPT choose No
  3. cfdisk partition: New → Primary → accept default size → Bootable → Write → type yes → Quit
  4. Format: Select vda1 → choose ext4 → Yes
  5. Bootloader & system: Install GRUB → Yes; Install /system as read-write → Yes
  6. Done: Wait for 100% then click "Mark as Installed" below - ApkBolt will restart and take over

If adb shows as disconnected afterward: in the VM window press Ctrl+Alt+F1, run setprop service.adb.tcp.port 5555, stop adbd, start adbd, then press Ctrl+Alt+F7 to return to the GUI.

Memory, CPU cores, rendering backend, ports, and acceleration are all chosen automatically. If startup fails, ApkBolt falls back gracefully - no manual intervention needed. ApkBolt uses a dedicated adb port 5044 (your system adb uses 5037), so the Android device won't appear in a regular adb devices call - this is intentional isolation. To connect manually, set $env:ANDROID_ADB_SERVER_PORT=5044 before running adb. Note: do not manually run adb connect against port 5555 - it will pop up an "Allow USB debugging?" system dialog over a running app.

App Window
Press F11 or right-click the tray to toggle at any time. Fullscreen just maximizes the window - it does not change aspect ratio or restart the app.
When on, every app opens fullscreen without pressing F11. Works best with landscape orientation - landscape apps naturally fill the screen without black bars.
Android's orientation is determined by the physical panel direction of the virtual device. If the panel direction doesn't match what the app requests, Android only gives it a narrow letterboxed strip. "Follow app" reads the orientation from the APK manifest at install time and restarts the panel to match - so portrait apps launch portrait and fill the window. A panel restart takes ~10-40 s but only happens once per orientation change.
Android's auto-rotate is on by default. This does not affect actual screen direction - panel orientation and the orientation policy above still control what the display shows. Only some apps that read this switch value are affected.
At 720px wide with 190 dpi, the logical width is 606dp - just past Android's 600dp tablet breakpoint. Disabling reverts to phone layout (larger text, less content). Takes effect on next app launch.
This is the current physical panel direction of the runtime, automatically set by the orientation policy above. Only in "Force" mode does it reflect a user choice.
Native window is rendered and managed by the emulator directly - drag, resize, and rotation all track perfectly, at the cost of a second taskbar button (use the tray or Ctrl+Alt+R for landscape). Embedded mode looks more integrated and adds a rotation button, but can drop frames and show black bars during resize, rotation, or app switching. Takes effect on next app launch.
In window mode you can drag the border freely; this sets Android's internal render resolution. Smaller = better performance.
Mouse Mapping
The emulator natively treats left-click as a finger tap; click-and-drag acts as a swipe. No extra setup needed.
By default the emulator treats right-click as a tap (easy to mis-trigger). Enable this to map right-click to Back instead.
Smooth mode batches scroll events over a short window into a single swipe gesture, avoiding jitter and preventing adb from spawning on every tick.
Side-button mapping requires a global mouse hook. The hook is installed only while an ApkBolt app window is in the foreground and removed immediately on blur or close - no desktop slowdown.
All mappings above are only active when an app window has focus; native Windows mouse behavior is fully restored when you switch away or close the window.

Container details (advanced)

Game mode keeps the Android VM at a high CPU priority and reduces host-side polling for minimum input and frame latency. Other apps on the system will run slower as a result.

The Android environment boots once and stays resident; subsequent app launches simply start the target app and stop others. Closing the last window parks the container; the next launch is still fast.

Drivers - Compatibility Patches
Some hardware needs specific launch flags to work correctly (old GPU with limited GLES support, missing hardware acceleration, driver versions that crash with hardware rendering). A driver is a JSON file: "match criteria" + "parameters to apply on match". You can write, import, and share them. Drivers only modify whitelisted launch options - no code is executed; unmatched drivers have no effect.

Runtime
ApkBolt exclusively runs its own managed runtime - adb, the emulator, and the system image are all downloaded and managed by ApkBolt itself. It does not detect, take over, or depend on any other emulator you may have installed (MuMu, LDPlayer, BlueStacks, WSA - none are touched). This means ApkBolt works the same regardless of what else is on your PC.
